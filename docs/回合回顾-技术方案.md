# 回合回顾（Turn recap）技术方案

> 实现于 `dsh-suggest-ghost-local` 0.5.0。产品目标：**每次 AI 输出完成后，用一行 80 字内的人话讲清这一轮之后什么变了**（结论、现在的状态、或还差什么），追加在回复末尾，重启后仍在；没有变化的回合不显示。

## 0. 写什么：变化量，不是过程摘要

回顾不是「这一轮的摘要」（摘要会覆盖正文、必然长），而是**这一轮之后的变化量**：读者只关心「这轮结束后，世界和我各有什么不同」。

- 决策回合：多了一个结论；交付回合：多了一个能用的东西；排查回合：多了一个事实；失败回合：多了一个阻塞点。
- 「一眼看懂」的四条判据：首句即主信息；一眼能判断「有没有我的事」；视线不跳（一行、无嵌套/并列堆叠）；不出现对话本身（禁「回顾 / 这一轮 / 我们 / 总结」式元叙述）。
- 落点：问句放在**材料**里（system 提示词保持用户定稿的三段不动），长度由代码整形闸门保证，没有变化的回合由模型回哨兵后静默跳过。

## 1. 形态与位置

一行，渲染在**助手最终回复之后、copy/fork/usage 动作行之前**：

```
🐳：开关已加上，构建通过，还有 1 条测试失败
```

- 挂载点：客户端槽 `conversation.chat.turnTail`（list / session 槽，官方定位是「已完成回合的动作行之前」的扩展点）。
- 注册 id：`dsh-suggest-ghost-recap`，`order: 10`（排在 schema 计划、deliverables 等自带条目之前）。
- 渲染：`🐳：`（图标 + 冒号，无文字标签）+ 斜体弱化正文；没有该回合回顾时组件返回 `null`，不占位。
- 样式只用 `--dsw-alias-*` token，不写 `document.body`、不 require 其它 UI 包（遵守插件扩展点规范）。

## 2. 触发

宿主监听 `session/event`：

| 事件 | 行为 |
|---|---|
| `turn/end` 且 `reason.kind === 'completed'` | 先照常触发下一条建议预测，再 `requestRecap(session, turn)` |
| `turn/start` | 作废旧预测（既有行为）；回顾按回合独立，不受影响 |
| `session/disposed` | 中止该会话在途回顾 |
| 插件卸载 | 中止全部在途回顾 |

`requestRecap` 的守卫（任一命中即跳过）：`recapEnabled === false`、子代理会话（`header.origin === 'subagent'`）、预测分支会话（防自激）、`turn <= 0`、该会话该回合已有回顾（幂等）。同一会话同一回合在途复用；同一会话更新回合时 abort 旧请求。

**为什么不是 Claude Code 的「离开 3 分钟」**：那是 idle-away summary，触发条件依赖终端失焦与缓存预热，语义是「你不在时发生了什么」。本插件要的是**每轮工作结束后的交接**，所以触发点放在回合完成，且每个回合独立成条（可按回看历史）。

## 3. 生成

一次**独立的辅助 LLM 调用**（不与预测、不与主会话共享请求）：

- 路由：配置里显式 `provider` / `model` 优先，否则继承父会话 `session.requestHeader()?.config`；缺路由记 `route_unavailable`，不调用模型。
- 材料（`buildRecapMaterial`）：只取**该回合**的事件桶（`turn/start` 切换），拼五段——
  - `[This turn — what the user asked for]`：用户消息（单条截 300 字符）
  - `[What the assistant concluded]`：本回合最后一条助手文本（截 1 500 字符）
  - `[Earlier narration in the same turn]`：更早的中间叙述（避免把过程流水账当结论）
  - `[Tool calls this turn (N)]`：工具名 + 目标（从参数 JSON 依 `file_path`/`path`/`command`/`pattern`/`query`/`url`/`description`/`prompt` 提取，截 180 字符，最多 24 条）
  - `[Tool errors this turn]`：工具错误原因
  - `[这一轮的结论]`：**问句**——「这一轮之后，什么变了？读者现在需要知道什么？」，附三条约束（只写结果/状态/缺口、不写过程不复述、不超过 `recapMaxChars` 个字），并约定「没有新的结论/状态变化/待办时只回复：无」。这是①优化的落点：同样的提示词，问「解决了什么」得到摘要，问「变化了什么」得到变化量。
  - 总预算 `recapSourceChars`（默认 12 000 字符）：超预算保头 40% + 保尾 55%，中间省略；问句在所有材料之后追加，永不被裁。
- 系统提示词（`recapSystemPrompt`）：按用户定稿只保留三段——角色与读者（这一轮用一段话说清；读者刚看完执行，只想听懂解决了什么、现在什么状态、还差什么）+「最高要求：逻辑清晰说人话，要解释给用户一次性就能够听明白」。**不再**在提示词里堆任何规则（顺序、句数、禁用词清单全部删掉，用户明确要求「下面的都删掉」）。
- 形状闸门（②）：`fitRecap` 先剥元叙述开头（「回顾这一轮：…」「这一轮把…」），再按 `recapMaxChars`（默认 80 字）整形——超长时按标点就近断句，保不住才硬截（按码点不劈代理对），最后去句尾悬空标点。宁可短一句完整的，也不要长一句断掉的。
- 无变化：`isNoChange` 认哨兵（`无` / `无变化` / `none` 等，容忍标点），返回 `no_change` —— 不落库、不推送、不显示。
- 收口：单次调用不重试（成本可控、失败静默）；`finish.kind` 与正文异常分别映射 `transport` / `timeout` / `abnormal_finish` / `tool_call` / `empty_body`。

## 4. 持久化

`suggest_ghost_recap` 域（`@deepseek-ai/dsh-storage-domain`，JSON 后端，与热度域同构）：

- 表 `entries`，键 `${sessionId}\u0000${turn}`，值 `{sessionId, turn, text, at, toolCalls?}`。
- 容量：单会话最多 50 条（按回合淘汰最旧）、全表 400 条（按写入时间整段淘汰会话）。
- 宿主未挂 `storageDomain` 时自动降级纯内存（能力探测，不报错）。
- 写入路径 fail-soft：落盘失败只 warn，不影响回合与回顾展示。

## 5. 下发与渲染

宿主 → client 走既有 `_push` 通道（协议 v2），新增两个字段：

```jsonc
{
  "recaps": [{ "turn": 3, "text": "…" }], // 按回合升序；无回顾为 null
  "recapsSessionId": "<sessionId>"        // 归属守卫：槽里装的是哪个会话的回顾
}
```

- `statePushOf(sessionId)` 是唯一权威组装点（pull 应答、启动对账、终态推送共用），所以回顾会随任何一次推送刷新。
- `fingerprintOf` 把回顾内容并入指纹，内容不变不重复写盘。
- client 侧：`applySettings` 解析 `recaps`/`recapsSessionId` 写入按会话的模块级 store（`useSyncExternalStore`），宿主 epoch 变化或 `connection/reset` 时清空；`TurnRecap` 组件按 `sessionId + turn.turn` 取文本。

## 6. 失败语义

| 失败 | 行为 |
|---|---|
| 无路由 | 记 `route_unavailable`，不调用模型，不显示 |
| 超时 / 传输错误 / 非正常结束 | 记对应 reason，不显示；主回合不受影响 |
| 模型返回工具调用 | 记 `tool_call`，丢弃 |
| 空正文（含只返回空白） | 记 `empty_body`，丢弃 |
| 模型回哨兵（无变化） | 记 `no_change`：不落库、不推送、不显示（「没变化的回合不显示」） |
| 落盘失败 | 只 warn；本次回顾仍会下发显示（内存态），重启后可能丢失 |

所有失败只写 `logger.debug`，不打扰用户，不产生错误气泡。

## 7. 配置

| 字段 | 默认 | 作用 |
|---|---|---|
| `recapEnabled`（volatile，可在设置卡片切换） | `true` | 总开关；关闭后不再生成，已生成的保留显示 |
| `recapMaxChars` | `80` | 回顾正文上限（字符）；超长按标点断句后硬截 |
| `recapSourceChars` | `12000` | 送给模型的回合材料预算（字符） |
| `recapTimeoutMs` | `30000` | 单次回顾调用截止时间（毫秒） |

输出令牌上限复用 `maxOutputTokens`（默认 8 192，实际不会写满）。

## 8. 验证

`scripts/recap-e2e.mjs`（已加入 `pnpm test:e2e`）：

- A：completed 回合恰好一次回顾调用，`_push.recaps` 携带 `{turn, text}`；
- A②：材料含五段标题、用户诉求、助手结论、工具调用与错误，末尾带「这一轮之后什么变了」问句与 80 字约束；路由继承父请求头；`tools` 缺省；提示词就位；
- C：`route_unavailable` / `transport` / `empty_body` / `tool_call` 四种失败归因且不调用（或不落库）；
- F：形状整形——超长按标点断句压到上限、元叙述开头被剥、哨兵「无变化」⇒ `no_change`；
- D：`recapEnabled: false` 时预测照常、载荷里没有回顾内容；
- G：回顾正文是哨兵时，线路不产生任何回顾推送；
- E：真实 storage 栈下 put → flush → 关闭 → 重新装配后 `list` 恢复（跨重启）。

`scripts/prediction-slice2-e2e.mjs` 在该功能后显式设 `recapEnabled: false`：那份文件断言 `llm.calls` 全是预测调用，回顾是独立链路，另有上面这套覆盖。

`scripts/prediction-client-e2e.mjs` 第 ⑤ 段（用最小 DOM 桩跑真实 `lib/client.js`，补一个假 `slots` 服务）：

- 注册项固定为 `{name: 'conversation.chat.turnTail', id: 'dsh-suggest-ghost-recap', order: 10}`，组件为函数；
- 有回顾的回合渲染 `div.fsr-recap`（带 `data-recap-turn` 与全文 `title`）；
- 没有回顾的回合、别的会话都返回 `null`（槽位条目不占位）；宿主换代（epoch 变化）后旧回顾不再渲染。

## 9. 设计取舍

- **不做会话事件**：插件不允许 append 新 type 的会话事件（live `Session.append()` 不能带 `ignorable: true`，会话重开会被拒），`appendPluginRecord()` 保留给 DSH 实验包。因此回顾走「宿主私有存储 + `_push` 下发」。
- **不用 `turnTail` 之外的槽**：`turnTail` 是唯一「回合已完成、动作行之前」的官方扩展点；`conversation.chat.node` 属于内部节点，replaceRisk 高。
- **独立调用而不是复用预测分支**：两者输入、输出、失败语义都不同（预测 JSON、回顾散文），复用会让预测的 `llm.calls` 断言与失败归因互相污染；独立调用的成本是每回合多一次小请求。
- **按 `sessionId+turn` 而不是会话级单条**：历史回看时每一回合都该有自己的一条；会话级只保留一条会让翻回旧回合时整行消失。
